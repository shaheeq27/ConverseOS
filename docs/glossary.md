# 📖 ConverseOS Terminology Glossary

| Term | Definition |
| :--- | :--- |
| **Organization** | The top-level tenant entity representing an enterprise or company (e.g. *Acme Corp*). |
| **Workspace** | A sub-tenant boundary within an organization (e.g. *Acme E-commerce Assistant* or *TechFlow SaaS*). |
| **Assistant** | An AI entity provisioned with a custom system prompt, model selection, temperature, tools, and knowledge sources. |
| **Conversation** | A stateful chat session between a user and an Assistant within a specific Workspace. |
| **Knowledge Source** | An uploaded file (PDF, DOCX, TXT) or URL ingested into the organization's knowledge base. |
| **Knowledge Chunk** | A token-bounded text snippet extracted from a Knowledge Source for vector indexing. |
| **Embedding** | A dense vector representation of a Knowledge Chunk generated by an embedding model. |
| **RAG** | *Retrieval-Augmented Generation*: Injecting relevant knowledge chunks into prompt context before LLM inference. |
| **Memory** | Contextual state persisted across conversations (User preferences, Workspace facts, Assistant history). |
| **Tool** | A function or API integration (e.g., Shopify, CRM, Webhook) callable by an Assistant during reasoning. |
| **Workflow** | An automated sequence of triggers and AI actions built visually with drag & drop components. |
| **Feature** | A self-contained, isolated functional module inside `src/features/`. |
| **API Envelope** | The standardized JSON structure (`{ success, data, error, meta, requestId, timestamp, version }`) returned by endpoints. |
